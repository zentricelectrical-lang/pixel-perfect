# Zentric Document & Job Management System

A private, phone-first workspace inside the existing admin area where the **job** is the central record. Built on the existing database (customers, jobs, quotes, invoices, payments, receipts, documents, audit logs) and extended, not replaced. Public website and brand stay as they are.

## Delivery order (each stage fully working before the next)

**Stage 1 — Core money workflow (first priority list)**
1. Admin workspace with mobile bottom-bar navigation and quick search (customers/jobs).
2. Dashboard: today's/upcoming jobs, new enquiries, pending quotes, jobs in progress / awaiting testing / completed, unpaid invoices, outstanding balance, payments received, recent customers & documents. Real data only, empty states when none.
3. Customers: list + search, create/edit (company, phone, WhatsApp, email, site address, notes), profile showing all their jobs, quotes, invoices, payments, receipts, warranties, agreements, documents. Convert an enquiry into a customer + job in one tap.
4. Jobs: create from customer or enquiry, 13 statuses (New Enquiry → Closed), and a **Job page** with a horizontal workflow timeline: Customer → Survey → Quote → Approval → Job Card → Materials → Testing → Invoice → Payments → Receipts → Handover → Warranty → Maintenance. Each step opens/creates its document pre-filled from the job.
5. Quotations: line items (qty, unit, unit price, labour/materials type), discount, tax, deposit, balance, scope, exclusions, assumptions, terms. Totals calculated by the database, never typed. Send/accept/reject, customer approval name + signature + date, duplicate.
6. Invoices: create from approved quote or blank; statuses Draft/Sent/Partially Paid/Paid/Overdue/Cancelled; balance derived only from recorded payments.
7. Payments: record M-Pesa/Cash/Bank/Other with reference; validated (no zero/negative, no overpay). Invoice balance and status update automatically.
8. Receipts: generated only from a recorded, confirmed payment, showing remaining balance.
9. PDF: branded A4 documents (logo, name, tagline, contact, number, date, customer/job, tables, signatures, footer) with Preview, Print, Download PDF, and Share (phone's native share sheet → WhatsApp, fallback WhatsApp link).

**Stage 2 — Field documents**
Site Survey, Job Card (created from approved quote), Material List (internal costs kept separate, never shown to customers), Testing Checklist (configurable checks; only technician-entered results, nothing pre-filled), Handover Certificate, Warranty (end date auto-calculated from period), Maintenance Agreement. Phone camera photo upload and finger signature capture.

**Stage 3 — Control & demo**
Locking: issued/completed financial documents become read-only; edits create a new version (history kept). Archive instead of delete. Audit trail for every create/edit/approve/payment/receipt/status change/archive. Clearly labelled DEMO records (one demo customer + job chain) with a "Remove demo data" button in Settings.

## Numbering
Switch new documents to the format you specified: ZEC-Q, ZEC-J, ZEC-MAT, ZEC-TST, ZEC-INV, ZEC-RC, ZEC-HO, ZEC-W, ZEC-MA (e.g. ZEC-INV-2026-0001), generated by the database so duplicates are impossible. Website enquiry/booking references (ZQ/ZB) stay as they are.

## Access
Owner (zentricelectrical@gmail.com) has everything. Roles extended with manager and finance for later; technicians see only assigned jobs; customers never see the internal workspace, costs or notes. Secure customer document links are left for a later version (architecture ready).

## Technical details
- New tables: site_surveys, job_cards, material_lists (+items), testing_records (+checks), handover_certificates, warranty_certificates, maintenance_agreements, document_versions; extra columns on quotes (scope, exclusions, deposit, approval fields, item type), invoices, customers (company_name), jobs (site address, statuses). All with GRANTs + RLS (staff full, technician assigned-only, customer own non-internal fields).
- Totals via triggers recomputing from items; payment confirm trigger updates invoice amount_paid/status; receipt insert validates payment CONFIRMED; lock trigger blocks edits on issued documents.
- Routes under `/admin/*` (customers, customers.$id, jobs, jobs.$id, quotes.$id, invoices.$id, documents.$type.$id), one shared document renderer used for screen, print and PDF (`@react-pdf/renderer` client-side), signature pad component, storage folder for job photos/signatures in the private bucket via signed URLs.
- Existing admin overview page becomes the dashboard; sidebar links become real routes.
